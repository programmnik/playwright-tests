# Test Plan

## Application Overview

Проверка формы обратной связи на странице /ru/contactus: корректная отправка валидных данных, валидация обязательных полей, обработка ошибок ввода и граничных случаев для длинного текста/спецсимволов.

## Test Scenarios

### 1. Contact Us Form

**Seed:** `tests/seed.spec.ts`

#### 1.1. Успешная отправка валидной формы

**File:** `tests/contact-us.spec.ts`

**Steps:**
  1. Открыть страницу https://automation.tivaliclub.com/ru/contactus в свежем состоянии браузера.
    - expect: Страница загружена, форма видима, поля Email, Тема обращения и Сообщение отображаются, кнопка Отправить активна.
  2. Ввести корректный email, например test.user@example.com.
    - expect: Поле email принимает значение без ошибок и отображает введённый текст.
  3. Ввести тему обращения, например 'Вопрос по подписке'.
    - expect: Поле Тема обращения заполнено и доступно для отправки.
  4. Ввести сообщение, например 'Здравствуйте, интересует возможность участия в клубе и стоимость участия.', в поле Сообщение.
    - expect: Текст отображается корректно, поле не обрезает символы и не деактивируется.
  5. Нажать кнопку Отправить.
    - expect: Форма отправлена без ошибок, пользователь видит подтверждение успешной отправки либо корректный результат в интерфейсе; страница не остаётся в состоянии с неочищенными данными без статуса.

#### 1.2. Проверка обязательных полей при пустом заполнении

**File:** `tests/contact-us-invalid-empty.spec.ts`

**Steps:**
  1. Открыть страницу формы в пустом состоянии.
    - expect: Все три обязательных поля пустые.
  2. Сразу нажать кнопку Отправить без заполнения любого поля.
    - expect: Система блокирует отправку, отображает сообщения валидации для Email, Тема обращения и Сообщение, пользователь остаётся на форме.
  3. Повторно заполнить только одно поле и отправить форму.
    - expect: Валидация помечает только незаполненные обязательные поля; заполненное поле остаётся корректным, остальные показывают ошибку.

#### 1.3. Невалидный email

**File:** `tests/contact-us-invalid-email.spec.ts`

**Steps:**
  1. Заполнить email значением 'test@example' или 'test@@example.com'.
    - expect: Поле помечено как некорректное, отправка не выполняется.
  2. Заполнить корректные тему и сообщение, затем нажать Отправить.
    - expect: Система не принимает форму, пока email не соответствует допустимому формату; сообщения об ошибке отображаются рядом с полем.
  3. Исправить email на корректный, например 'test.user@example.com', и отправить повторно.
    - expect: Ошибка исчезает после исправления, форма отправляется успешно.

#### 1.4. Поля заполнены только пробелами

**File:** `tests/contact-us-whitespace.spec.ts`

**Steps:**
  1. Ввести в Email строку '   ', в Тема обращения — '   ', в Сообщение — '   '.
    - expect: Система трактует такие значения как пустые; не должно быть успешной отправки.
  2. Нажать Отправить.
    - expect: Показаны ошибки в обязательных полях, форма остаётся на исходной странице.
  3. Заменить пробельные значения на реальные значения и повторить отправку.
    - expect: После корректного заполнения форма проходит валидацию и отправляется успешно.

#### 1.5. Граничное значение: длинный текст

**File:** `tests/contact-us-long-text.spec.ts`

**Steps:**
  1. Заполнить Email корректным значением, тему коротким текстом и сообщение максимально длинным допустимым текстом (например, 2000–5000 символов, если такой лимит установлен).
    - expect: Поле принимает длинный текст без падения верстки и без потери части символов.
  2. Нажать Отправить.
    - expect: Форма либо успешно отправляется, если лимит не превышен, либо отображается сообщение о превышении допустимой длины без потери данных.
  3. Проверить, что интерфейс остаётся стабильным после попытки отправки и нет обрушения/зависания страницы.
    - expect: Страница остаётся отзывчивой, нет JS-ошибок и нет исчезновения формы.

#### 1.6. Спецсимволы и Unicode

**File:** `tests/contact-us-special-characters.spec.ts`

**Steps:**
  1. Заполнить Email значением 'тест.user+tag@example.com' или 'user.name+test@sub.domain.co.uk'.
    - expect: Поле принимает значение с допустимыми символами и не блокирует ввод.
  2. В тему обращения ввести текст с кавычками, тире, цифрами и символами: 'Вопрос "по оплате" — 2026/07/15 №42'.
    - expect: Текст корректно отображается, поле не ломается и не обрезает символы.
  3. В Сообщение ввести текст на русском, английском и с символами: '!@#$%^&*()_+[]{};:,./<>?~`', а также строки с переносами и эмодзи.
    - expect: Форма корректно хранит и отображает введённый текст; отправка возможна при корректной валидации.
  4. Нажать Отправить.
    - expect: Система либо корректно принимает форму, либо валидирует только действительно запрещённые символы, но не ломается и не теряет введённые данные.
